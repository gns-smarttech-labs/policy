Webhook API Integration Specification

Automated Contact Synchronization Protocol

When a webhook URL is configured, Business Card Scanner dispatches contact sync events to your custom endpoint using HTTP POST with Content-Type: application/json.

⚠️ Security Notice & User Disclaimer

Notice: External webhook endpoints receive complete contact record payloads. If an untrusted third party asks you to configure their webhook URL, they may be able to fetch and store all your contacts. Only add endpoints you own, control, or trust. Our application and developers bear no responsibility or liability for any third-party endpoints or their handling of transmitted data.

📡 Request Specification

Protocol & Method: HTTPS (TLS 1.2+)  |  POST
Headers: Content-Type: application/json
X-Device-Id: <unique_device_id>
X-Webhook-Signature: <secret_key> (Default: default)
X-Webhook-HMAC-SHA256: <hex_digest>
Authorization: Bearer <token> (Optional custom header)
X-Api-Key: <api_key> (Optional API key)
Body: JSON Array of Webhook Action Objects

🛡️ Essential Security Mitigation Strategies

To ensure bulletproof endpoint security, Business Card Scanner implements three industry-standard mitigation strategies:

1. Enforce HTTPS (TLS 1.2+)

By default, the application requires and strictly enforces https:// for all webhook endpoints. Insecure plain HTTP dispatches are rejected prior to transmission to prevent eavesdropping and man-in-the-middle attacks on public networks.

2. Validate HMAC-SHA256 Signatures

Each outgoing payload is cryptographically hashed using HMAC-SHA256 with your shared secret key. The resulting digest is sent in the X-Webhook-HMAC-SHA256 header. Receiving servers should verify this signature before processing contacts:

Node.js (Express) Signature Verification 
const crypto = require('crypto');

function verifyWebhook(req, res, next) {
  const signature = req.headers['x-webhook-hmac-sha256'];
  const secret = process.env.WEBHOOK_SECRET || 'default';
  const expected = crypto.createHmac('sha256', secret)
                         .update(req.rawBody)
                         .digest('hex');

  if (!crypto.timingSafeEqual(Buffer.from(signature || ''), Buffer.from(expected))) {
    return res.status(401).json({ error: 'Invalid HMAC signature' });
  }
  next();
}
Python (FastAPI / Flask) Signature Verification 
import hmac, hashlib

def verify_webhook(raw_body: bytes, signature_header: str, secret: str = 'default') -> bool:
    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(signature_header, expected)

3. Custom Authorization Headers (Secret API Key or JWT)

If your webhook receiver or API Gateway (e.g. AWS API Gateway, Kong, Cloudflare Workers, Supabase) requires Bearer tokens or API keys, configure the optional Custom Authorization Header in app settings. The app automatically dispatches:

  • Authorization: Bearer <token>
  • X-Api-Key: <key>
  • X-Device-Id: <device_id> (Enables per-device rate limiting and auditing)

📥 Response Expectation

Your endpoint or CRM middleware (e.g. Zapier, Make, HubSpot) should return an HTTP status code in the 200–299 range to indicate successful delivery.

Expected Response Body (JSON)

  "status": "success",
  "message": "Processed 1 contact(s)"
}
